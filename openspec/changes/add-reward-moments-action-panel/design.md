# 设计与接入规则

## 布局

在用户概览现有活动区域附近放置一个统一区域。标题“你现在能获得什么”，个人行动约占桌面宽度 62%，匿名奖励动态约占 38%。一个有浅色底的推荐行动加三条紧凑活动入口，不重复堆叠三张大卡。手机按 DOM 顺序先个人行动、再动态、最后钱包。无公开动态或动态失败时个人区域占满宽度；动态失败不影响参与活动。

沿用既有语义色：浅背景、白色面板、slate 正文、teal 可操作与到账状态，amber 仅辅助区分抽奖。系统字体适配中英文，正文 12–14px、标题 18–22px、重点金额 34–38px，金额使用等宽数字。Grid 定义主次区域、Flex 排列内容、容器查询适配嵌入位置；保持 DOM 与视觉阅读顺序一致。

## 个人行动

推荐优先级：阻断状态明确说明 → 最早到期的有效待领奖励 → 今天可领的签到 → 已有抽奖次数 → 合适的参与说明。未满足门槛不显示为可领取；无法确定的金额不承诺，抽奖只显示次数，不将期望奖励与可领金额相加。

- 消费奖励：显示可领取金额与最近领取截止时间（北京时间）。首版沿用现有活动选择逻辑；存在多个期次时，每次只领取明确的当前期次，不展示跨期总额却仅领取一期。点击“领取 $金额”调用该期现有领取接口，成功后刷新钱包及状态，防止旧刷新覆盖新结果。
- 签到：仅在服务端确认资格且 next_reward_cents > 0 时显示“签到领 $金额”，金额包含当天实际里程碑和上限裁剪。未达标显示实际缺少条件，可查看现有签到说明；不在前端硬编码门槛。
- 抽奖：显示剩余可用次数；“去抽奖”打开现有九宫格，不自动扣次数，奖项、概率和历史记录不变。没有次数先查看规则，用户主动充值才进入 `/purchase`。
- 首次参与：按服务端实际条件展示引导，不承诺立即到账。
- 活动关闭与发奖暂停分开：停止新增资格不自动废弃有效待领奖励或已发次数。全局发奖暂停、活动暂停、退款复核、欠额、预算不足等以现有服务端对应动作的真实允许状态为准。预览提供独立“发奖暂停”“停止新增资格”“退款复核”场景。
- 错误与提交中：正在提交时禁止重复点击；明确失败保留金额及重试入口；超时或未知状态先刷新服务端确认结果，不盲目重新抽奖或扣款。提示只朗读本人的操作结果，公开动态不使用 live region。

## 钱包

底部单独显示“奖励钱包 · 已到账”及“全部转入余额 $金额”。待领取奖励不计入可转入余额；领取成功后显示下一步。转入复用现有接口，不增加一次额外确认流程：预览对话框仅用于展示成功/失败状态，生产沿用现有一步转入体验。成功后先更新钱包、再刷新账户余额；账户资料刷新失败不得把已成功转入显示为失败。个人页面不得将奖励描述为现金提现。

## 公开动态

标题“其他人的奖励时刻”，默认静态最近三条，可展开到六条，避免跑马灯干扰。动态来自真实、已提交的奖励入账：签到、抽奖、已领取的消费奖励、其他实际入账的营销奖励；不展示待领取、处理中、失败、转入余额和人工测试记录。按来源幂等去重，被退款回收或撤销的原奖励移除；不只筛选大奖，不改变或暗示中奖概率。记录显示明确发生时间与时区，不把旧记录重放成“刚刚”。

动态里的活动名称只定位/聚焦对应个人入口，不直接执行领取、充值或抽奖；不能向用户泄露其不可见或不在受众范围内的活动。

隐私默认不公开，用户可选择允许匿名展示且可随时撤回。别名由服务端生成，窗口内稳定、与公开用户标识不可反推；接口不返回 user_id、邮箱、用户名、充值/消费金额或余额。公开接口必须同时过滤服务端受众可见性、用户授权与事件状态，前端匿名化不能代替后端过滤。

后台独立总开关默认关闭，关闭后客户端立即清空公开动态并停止刷新，个人活动不受影响。先使用小流量白名单，无需 WebSocket；可按可见性定时读取带缓存的只读投影（例如 60 秒），页面隐藏暂停。限制时间范围、页大小与请求频率；不要为每个访客扫描整个资金账本。退款、撤回公开授权、管理员关闭需使缓存失效。正式接入需要新增隐私与展示配置及可索引公开事件投影，前向迁移，不修改已有资金历史。

## 已确认的预览设计记录

原 `/preview/reward-moments.html` 为独立 Vue 预览，顶部标注示例数据，所有行为仅修改内存状态。支持中英、明暗、可领/首次/已领/发奖暂停/停止新增/复核/无动态/动态失败场景；领取和签到演示钱包同步，转入演示提交中、成功和失败重试。抽奖按钮展示复用现有九宫格的交接位置，不模拟开奖结果。用户确认后已完成下述正式接入，原型文件已清理。

真实接口的受众、隐私、撤销及前端并发和旧响应覆盖回归已完成，详细结果见 `validation.md`。实际部署与登录态验收尚未进行。

## 正式接入决定（2026-11-26）

- `RewardActionPanel.vue` 接入概览，复用现有领取、签到和转入 API；抽奖及签到说明通过事件打开现有顶栏弹窗，消费详情定位原进度组件。当前期次优先选择最早到期的预留奖励，领取只提交该期 ID。
- 新增迁移 `269_activity_reward_moments.sql`，在奖励钱包入账的同一事务内维护公开投影。不回填历史，不向核心账务表添加触发器或外键。校验签到、抽奖批次和已领取权益来源；转入、人工无来源入账不投影。消费权益撤销/复核及抽奖撤销删除原动态。
- 用户默认不授权，仅授权后新获得的签到、抽奖和消费奖励可展示。撤回即时从服务端查询排除，再次授权不重新公开旧事件。匿名别名用服务端随机密钥 HMAC 生成，在北京时间自然周内稳定，不返回来源或用户标识。
- 展示开关独立、默认关闭；首版只向后台配置的最多 500 个用户开放，空名单无人可见。后台入口在营销活动各子页顶部；用户授权入口位于个人行动区底部，已有授权时保留区域便于撤回。
- 不使用共享响应缓存；公开接口 `Cache-Control: private, no-store`，每次检查授权、受众和事件状态。只查最近七天的索引投影、最多六条，并使用现有用户请求限流。可见页面每 60 秒检查配置，后台关闭在服务端下次请求立即拒绝展示，客户端收到关闭即清空并停止拉取动态；配置检查保留以识别再次开启。页面隐藏暂停网络刷新。
- 临时原型和联调挂载在验证后清理，正式页面没有 mock 数据或预览开关。实际登录与部署验收另行完成。
