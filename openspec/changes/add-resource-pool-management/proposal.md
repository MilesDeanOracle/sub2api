## Why

账号与分组通过多对多绑定共同决定实际可调度资源池，但当前分别位于两个管理菜单，管理员需要反复切换页面才能完成“建分组、加入账号、检查可用性、调整组内关系”的连续工作。新增统一资源池工作台可以围绕分组上下文完成日常维护，同时保留账号和分组各自独立的领域含义。

## What Changes

- 新增 Element Plus 实现的“资源池管理”菜单与页面，以左侧分组导航、右侧账号池为主要布局。
- 提供“全部账号”和“未分组账号”两个虚拟视图，并按平台组织真实分组。
- 选择分组后展示其摘要、可用/限流/总账号数，并允许查看、筛选和维护该组账号。
- 支持在当前分组上下文中新建账号、添加现有账号、批量加入或移出账号，以及调整账号的组内优先级。
- 提供分组创建与编辑入口，并将复杂的分组设置继续交给现有分组编辑能力处理，避免复制业务逻辑。
- 提供“上游账号管理”抽屉：管理员输入兼容 Sub2API 的上游 Base URL 与管理员 API Key，按现有分组接口探测并以表格查看上游全部分组；探测凭据不持久化。
- 将原“账号管理”和“分组管理”侧边栏入口合并为“资源池管理”；保留原路由并重定向到统一工作台的对应视图，兼容收藏链接和站内跳转。
- 不改变现有账号、分组、账号分组关系的数据模型和后端 API 语义。

## Capabilities

### New Capabilities

- `resource-pool-management`: 管理员在统一 Element Plus 工作台中浏览分组、管理账号与分组关系，并从旧管理入口平滑进入相应上下文。

### Modified Capabilities

无。

## Impact

- 前端路由、管理端侧边栏及相关导航文案。
- 新增资源池管理视图及可复用的 Element Plus 组件。
- 新增受管理员鉴权保护的上游分组探测端点，服务端转发兼容的 `/api/v1/keys` 请求并聚合其中的分组，以避免浏览器跨域和凭据暴露。
- 复用现有账号、分组和绑定关系 API；如现有接口不能高效完成组内批量操作，仅做最小的前端编排或补充兼容接口。
- 原 `/admin/accounts`、`/admin/groups` 路由继续可用，但不再作为独立侧边栏菜单展示。
- 需要补充路由、菜单、分组上下文、账号绑定和关键交互测试。
