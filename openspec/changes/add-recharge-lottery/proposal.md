# 充值送抽奖（神秘宝箱）站内活动提案

## Why

为提升用户单笔在线余额充值意愿与复充体验，在不修改核心表结构的前提下，新增常驻开关型「充值送抽奖（神秘宝箱）」营销活动：用户单笔人民币余额充值每实付满 `¥10` 赠送 1 次开箱机会，100% 必中 6 档美金奖励并统一入账独立活动奖励钱包（`activity_wallets`）。

## Core Rules

1. **赠次口径**：仅计在线余额充值订单（`order_type = 'balance'`、`status = 'COMPLETED'`、渠道结算币种 `CNY`），按单笔实付 `floor(pay_amount / 门槛)` 向下取整（默认每满 `¥10` 送 1 次），零头不跨单累计；仅统计活动开启时间窗（`activity_lottery_windows`）内完成支付的订单，不追溯开启前的历史老订单。
2. **奖池与期望成本**：固定 6 格奖位且 100% 必中，金额与正整数权重支持运营台配置；默认预置 `$0.5(88%) / $1(9.5%) / $3(2%) / $5(0.4%) / $10(0.09%) / $50(0.01%)`（单抽期望 `$0.629`，按 `1:1` 折算名义返赠比例约 `6.29%`）；支持单抽与纯快捷十连抽（10 次独立同分布随机，无额外保底）。
3. **预算护栏**：设独立的「抽奖活动总预算」，与签到和各消费活动独立配置、独立核算，不受「单用户终身奖励上限」限制；当剩余可用预算不足以覆盖本批最高档峰值（单抽 `< 最高档`、十连 `< 10 × 最高档`）时暂停开箱并保留次数，绝不暗改概率。
4. **入账与退款风控**：奖金统一写入 `activity_wallets` 由用户手动一键转入 `users.balance`（自动累加 `unabsorbed_gift` 防消费阶梯套利）；抽奖次数不过期，关闭活动仅停止新充值赠次；订单退款处理中冻结该用户抽奖与提现，退款成功后自动按未退实付重算并扣回差额次数；已经使用的无效次数按原订单逐次归属扣回对应奖励，依次使用活动钱包与未冻结账户余额。普通退款无法同时覆盖本金和奖励时在调用渠道前拒绝，强制或渠道侧已完成退款的不足额记录为待回收欠额并冻结活动转入，待补足与人工复核。

5. **规则稳定性**：赠次窗口开启、存在未用次数或待同步合资格订单时禁止修改奖额与权重，独立预算仍可调整。未用次数的期望奖金在运营台展示，预算不足时提醒补足；该指标不是保证所有次数最高奖金的资金预留。

## Non-goals

- 不修改 `users`、`payment_orders`、`usage_logs` 等核心表结构，不添加数据库触发器或指向核心表的外键。
- 退款流程在调用渠道前，以 users → activity_wallets → payment_orders 锁序原子保留本金与对应奖励；成功结算，失败原子恢复，pending 保留至渠道终态。支付履约回调和核心充值视图不改动。
- 首期不提供后台手工增减抽奖次数、十连保底或非 `CNY` 币种赠次。
