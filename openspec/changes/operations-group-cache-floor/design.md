# 设计

- 列表范围与公开快照一致：状态为启用且非专属的分组，排序相同。每行携带内部分组 ID，仅管理员接口返回，公开快照不暴露。
- 配置键为 `public_transit_group_cache.<分组ID>`，值为 `{ "enabled": bool, "floor": number | null }`。按行 upsert，两位管理员同时修改不同分组不会互相覆盖。调整值须大于 0 且小于 100，最多一位小数；为空或状态为暂停时不调整。
- 比对按窗口独立进行，累计、近 7 天、近 24 小时使用同一个调整值。真实命中率低于调整值时，输入与缓存创建 token 不变，缓存命中 token 放大为 `调整值 × (输入 + 创建) / (100 − 调整值)` 后取整，命中率返回调整值。真实命中率不低于调整值，或窗口内没有任何提示词 token 时，保持原值。
- 管理员列表始终返回真实命中率，不经过调整。页面打开时加载一次并提供手动刷新，不做定时轮询，避免反复对 usage_logs 全表聚合。
- 列表同时返回累计窗口的真实 token 明细（缓存命中、缓存创建、输入），在「Token 明细」一列分三行按 K/M/B 紧凑单位显示，与真实命中率同源、不经过调整。
- 表格上方是查询表单：分组名称（不区分大小写的包含匹配）、平台（选项来自平台清单）、启用状态。点「查询」或在名称框按回车才带条件请求后端，由后端过滤；「重置」清空条件并重新查询。刷新按钮沿用最近一次查询的条件。在状态查询下切换某行开关后，会重新查询，避免留下不再符合条件的行。
- 列表接口固定返回 `{ items: [...] }`。通用响应封装的 `data` 字段带 `omitempty`，直接返回空数组时该字段会被省略，前端会拿到空值。
- 页面「累计缓存命中率」显示真实值；「调整值」点击后就地编辑，回车或失焦保存，Esc 取消；「状态」为行内开关。启用且真实命中率低于 70% 时，「累计缓存命中率」以红色显示。
- 接口挂在 `/admin/operations/group-cache`，沿用管理员认证与审计中间件，并拒绝受限管理员密钥。
