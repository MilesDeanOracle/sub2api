# 消费阶梯奖励实施与操作说明

本地实施完成，活动尚未创建或发布。候选三档仅用于新建表单默认值，不代表生产发奖授权。

## 操作入口

后台：**运营台 → 营销活动**，下设“签到奖励”（`/operations/rewards/checkin`）和“消费奖励”（`/operations/rewards/consumption`）。旧地址 `/operations/rewards` 自动进入签到奖励。共用总预算与个人累计上限在签到奖励页面配置，消费奖励页面提供跳转链接。

1. “签到奖励”页面的“增长活动配置”设置共用总预算与单用户累计上限；签到仍使用原有独立月预算、门槛和最多 $15 月上限。这里显示的累计已用包含消费奖励预留，历史二充奖励仍计入总支出。
2. “历史余额确认与消费审计”查询用户 ID，根据充值凭证确认待确认余额来源。此操作不增减可用总余额、不追溯已消费的历史资金。未经确认的历史余额仍正常可用，但不计奖励进度，也不能作为本金退款。
3. 新建活动，设置北京时间的起止、领取截止、参与比例、预算和三档金额；先保存草稿，再发布**已保存版本**。默认 30 天、结束后 7 天领取、10% 用户 ID 稳定分组，预算必须自行配置。试验组尚未按历史活跃度分层；需结合实际人群分析，不能直接据达标用户数据宣称因果提升。
4. 必须在开始前发布；发布时间后冻结活动时间、分组和档位，只允许增加预算。暂停和结束均停止新增进度，保留已预留奖励的领取能力。暂停不可恢复，后续请新建一期。
5. 用户仪表盘在账户统计下方显示紧凑阶梯进度条；未发布时不显示营销卡。顶栏每日签到入口保留，原二充卡片与配置入口已撤下，新二充发奖已关闭，历史记录保留。

## 账务实现

- `users.balance` 继续作为可用总余额，独立 `activity_*` 表保存本金、赠额、待确认来源及逐笔分摊；数据库触发器覆盖所有余额变动。
- 支付订单处于实际支付履约阶段，且余额兑换码、用户、金额相符，才将到账扣除充值赠金后的部分计为本金。未标记来源的其他正向调额、兑换码、签到及阶梯奖励归赠额。
- 扣费顺序：赠额 → 待确认 → 本金；统一结算事务携带请求 ID、密钥 ID 和请求类型，只有普通本金结算计进度。订阅不扣余额，Cyber 排除。兼容旧扣费回退路径只分摊资金，不猜测有效消费。
- 消费精度为 8 位，展示消费金额向下取两位，下一档差额向上取两位，资格由服务端原始精度判断。
- 批量图片任务在冻结时保存来源组成，最终捕获才累计实际本金消费，释放按原来源返还；升级前的未知冻结资金返还到待确认。
- 来源流水在扣费事务内写入持久outbox，后台任务按原结算时间判定归属；奖励允许短暂延迟，失败退避重试。异步达标后按档预留完整奖励，共用总预算、个人累计上限、本期预算同时约束；领取锁用户与共用预算，唯一活动/用户/档位与奖励流水双重去重，入账后失效缓存。
- 预留到领取截止自动在预算计算中失效，不依赖后台定时任务；状态和历史查询显示过期。审核中的未领预留保留占用，直至管理员处理。
- 任意余额退款状态事件阻断新奖励并将已有未领资格转待审。退款扣减最多使用已确认本金，失败返还保留本金属性。消费冲正撤销对应奖励进度，不自动改变实际余额；已发奖励不自动负扣，须人工核验并记录处理证据。

## 与初稿的明确差异

本次使用与扣费同事务落库的结算分摊台账，时间取实际结算时间，不依赖异步 usage_logs 写入；因此日志晚到不会丢失活动进度；262迁移增加独立奖励任务，可靠队列与来源流水同事务写入，无独立24小时日志回填任务。截止后才发生的结算不归入上一期，人工冲正保留原结算时间。若以后接入外部、延迟到达且带独立发生时间的结算事件，需再补接收宽限与事件验签，不能直接回写时间。

暂停为不可恢复的停止，避免暂停期间消费被恢复后的汇总回算。当前后台提供参与人数、达标人数、已发和预留金额；留存、毛利及试验效果仍需运营分析，没有自动生成统计显著性结论。

## 验证

- Go 活动、签到、统一结算、批量冻结和退款相关测试。
- 可重复的 PostgreSQL 隔离 schema 测试：`ACTIVITY_TEST_DSN='postgresql://…' go test ./internal/service -run TestConsumption -count=1`。测试自建、自清理 schema，不修改站点用户或活动；覆盖来源确认、混合扣费、充值赠金、退款、最小精度边界、12 路并发领取、预算完整预留、Cyber 排除、批量冻结/捕获/释放、费用冲正与领取过期。
- 前端类型检查、中英文键完整性、金额配置与 8 位消费边界测试。
- 实际 Vue 组件的模拟数据浏览器检查：桌面三节点、390px 移动列表、深色模式、后台新建草稿、无横向溢出。预览不连接发奖接口，完成后删除临时页面。

## 生产加固与仪表盘

262默认关闭处理及发奖，启用顺序和历史资金核验见 [production-rollout.md](production-rollout.md)。不配置开关时，用户不能签到或领取奖励，这是部署保护而非活动表单失效。

仪表盘使用服务端真实档位与有效消费，展示下一档差额、达标/预留/已领状态，支持领取、展开规则及历史。每30秒、窗口重新聚焦或页面重新可见时更新。保留8位资格精度，以原生带标签progress提供辅助技术进度语义，移动端在卡片内部横向滚动。领取资格以服务端预留为准，视觉达标不等于可领取。这里统计消费奖励，充值本身不推进阶梯。
